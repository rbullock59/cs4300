# Homework 2: Movie Theater Booking (Django + DRF)

A RESTful movie theater booking application. Users can view movie listings,
book seats, and check their booking history — both through a JSON API
(Django REST Framework) and through a Bootstrap-styled web UI (Django
templates) that drive the same underlying data.

## Project structure

```
hw2/
├── movie_theater_booking/   # Django project (settings, urls, wsgi)
├── bookings/                 # App: models, serializers, views, templates, tests
│   ├── models.py              # Movie, Seat, Booking
│   ├── serializers.py         # DRF serializers
│   ├── views.py                # DRF viewsets + template views
│   ├── urls.py                 # Template page routes
│   ├── api_urls.py             # /api/ routes (DRF router)
│   ├── templates/bookings/     # base.html, movie_list.html, seat_booking.html, booking_history.html
│   ├── management/commands/seed_demo_data.py
│   └── tests.py                # Unit + integration tests (DRF APITestCase)
├── features/                  # Behave BDD tests
│   ├── booking.feature
│   ├── steps/booking_steps.py
│   └── environment.py
├── requirements.txt
├── Procfile                   # Render start/release commands
└── render.yaml                # Render service definition
```

## Setup

```bash
cd hw2
python3 -m venv myenv --system-site-packages
source myenv/bin/activate
pip install -r requirements.txt

python manage.py migrate             # also seeds 3 demo movies + 9 seats
python manage.py createsuperuser     # optional, for /admin/

python manage.py runserver 0.0.0.0:3000
```

Then open the DevEdu "app" link, or `http://localhost:3000/` locally. Sign up for an
account at `/accounts/signup/` (linked from the nav bar) to book seats.

Demo data is seeded automatically by migration `bookings/0002_seed_demo_data`, so
it runs on every fresh database — local or Render. To re-seed or add more sample
data on an existing database, `python manage.py seed_demo_data` is also available
(idempotent, safe to re-run).

## API endpoints

| Endpoint | Methods | Description |
|---|---|---|
| `/api/movies/` | GET, POST, PUT, PATCH, DELETE | List/create/update/delete movies (read is public, writes require login) |
| `/api/seats/` | GET, POST, PUT, PATCH, DELETE | Seat availability (read is public, writes require login) |
| `/api/bookings/` | GET, POST, DELETE | Book a seat / view your own booking history (requires login) |

## Web UI routes

| Route | Description |
|---|---|
| `/` | Movie listing |
| `/movies/<id>/book/` | Seat picker + booking form for a movie |
| `/bookings/history/` | Logged-in user's booking history, with a Cancel action per booking |
| `/accounts/signup/` | Create an account |
| `/accounts/login/`, `/accounts/logout/` | Auth (Django's built-in auth views) |
| `/admin/` | Django admin |

## Testing

```bash
# Unit + integration tests (Django/DRF)
python manage.py test bookings

# Coverage report
coverage run --source=bookings manage.py test bookings
coverage report -m      # ~93% coverage on bookings/

# BDD tests (Behave)
python manage.py behave
```

## Deployment (Render)

This repo includes a `render.yaml` and `Procfile` for a Render **Web Service**:

- Build command: `pip install -r requirements.txt && python manage.py collectstatic --noinput`
- Start command: `python manage.py migrate --noinput && gunicorn movie_theater_booking.wsgi:application`
- Env vars: `SECRET_KEY` (auto-generated by Render), `DEBUG=False`. Render automatically
  sets `RENDER_EXTERNAL_HOSTNAME`, which `settings.py` adds to `ALLOWED_HOSTS`.
- Static files are served via WhiteNoise, no separate CDN needed.
